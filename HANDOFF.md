# HANDOFF: Flutter-интерфейс FloatingDock

Ветка `flutter-ui`. Код WinUI-версии (`src/FloatingDock.App`) в репозитории остаётся, но в релизы 2.x она не входит.

> **ПРАВИЛО СБОРКИ (требование пользователя).** Собранный результат всегда кладётся в папку релиза `..\release-2.0.1` (Portable, zip, Setup, `SHA256SUMS.txt`). **Не создавать `.validation\dist5` и другие `dist*`/`engine*` папки и не городить свои сборочные папки.** Как это делать, см. абзац «Релиз (как собирать сейчас)» ниже. Для быстрой проверки на экране запускать `release-2.0.1\Portable\FloatingDock.exe` (закрывать `--quit`).

## Архитектура (решения)

- **Движок** `src/FloatingDock.Engine` (net10, win-x64, self-contained, WinExe): вся системная логика (трей, горячие клавиши, панель задач, список окон, настройки, иконки, медиа, сеть, звук). Без окон.
- **UI** `ui_flutter/app` (Flutter, только Windows): один процесс, один движок Flutter, много нативных HWND (`FlutterDesktopViewControllerCreate`), в Dart `runWidget` → `ViewCollection`. Дополнительные окна не уничтожаются, а прячутся и переиспользуются (ленивое создание).
- **IPC**: TCP на 127.0.0.1 (случайный порт + токен в `hello`), адрес `tcp:<порт>:<токен>` лежит в `<профиль>\engine.endpoint` и передаётся UI как `--socket`. JSON по строкам. Unix-сокеты убраны: на Windows 26300 connect даёт 10022, файлы мёртвых сокетов не удаляются (1920). Протокол: `ui_flutter/protocol/PROTOCOL.md`; зеркала: `src/FloatingDock.Ipc/Protocol.cs` и `ui_flutter/fd_ipc/lib/protocol.dart`.
- **Прозрачность**: только `DwmExtendFrameIntoClientArea(-1)`, WS_POPUP, topmost, tool window, NOACTIVATE; поля 28 DIP вокруг контента, без регионов окна и без blur рабочего стола в анимируемых окнах (ничего не обрезается).
- **Состояние**: `AppState` (настройки, закрепления, окна, тексты, иконки, тема), оптимистичные обновления с коалесцированием 60 мс.
- **Тема**: `ColorScheme.fromSeed` (мята 4E9F75 по умолчанию, графит 5F6368), светлая и тёмная; верхняя панель всегда тёмная.
- **Движение**: `PopSurface`, `Reveal`, `GlideList`, `GlideScope/GlideRow`, `WavyProgress` (`lib/ui`). Анимации WinUI не менялись.
- **Док**: один `CustomPainter`, математика (`dock_math.dart`) — порт Magnification/DockMotion/DockLayout, поддержаны Bottom/Left/Right.
- **Выбор интерфейса**: настройка `UiMode` ("Flutter" по умолчанию / "Classic"), переключение в Настройки → О программе → Интерфейс; движок и WinUI передают управление друг другу.
- **Раскладка сборки**: `<dist>\FloatingDock.Engine.exe` + `ui\fd_ui.exe` + (необязательно) `classic\FloatingDock.exe`.
- **Сборка Flutter**: только `flutter build windows --release --no-tree-shake-icons` (иначе tree-shaking режет шрифт иконок Material).
- **Диагностический профиль** (`--diagnostic-profile <папка>`): без трея, горячих клавиш, автозапуска, скрытия панели задач и прогрева закреплений «Пуска». Нужен для безопасных проверок на копии профиля.

## Как собрать и запустить

```powershell
# движок
dotnet build src\FloatingDock.Engine\FloatingDock.Engine.csproj -c Release -o .validation\engine1
# UI (из ui_flutter\app)
flutter build windows --release --no-tree-shake-icons
# сборка папки (ui_flutter\tools)
.\make-dist.ps1 -SkipClassic            # без WinUI; без флага собирает и classic\
.\.validation\dist1\FloatingDock.Engine.exe    # запуск: движок сам поднимает UI
```

Проверки:

- `flutter test` в `ui_flutter\app` — виджет- и golden-тесты (шрифты берутся из Windows).
- `ui_flutter\tools\with-engine.ps1` — IPC-проверки `fd_ipc\tool\ipc_check*.dart` против живого движка на диагностическом профиле.
- `ui_flutter\tools\live-check.ps1 -Shots <папка> [-Quick]` — живой прогон на копии профиля: скриншоты, холостая нагрузка, чистое завершение.

**Релиз (как собирать сейчас).** Всегда собирать в последнюю релизную папку (`..\release-2.0.1`), а не в `dist*`: это прямое требование пользователя. `packaging\release-flutter.ps1 -Out <папка>` отказывается писать в существующую папку, поэтому: собрать в пустую временную папку (`-SkipTests`, если тесты уже прошли), убедиться, что `FloatingDock.exe` и `fd_ui.exe` не запущены, затем заменить в `release-2.0.1` каталог `Portable\`, zip, установщик и `SHA256SUMS.txt` и сверить хэши. Окружение: `DOTNET_CLI_HOME=..\.build-tools\cli-home`, `NUGET_PACKAGES=..\.build-tools\nuget`, в `PATH` `..\.build-tools\dotnet` и `C:\dev\flutter\bin`. Сборка ~4 мин; код выхода 1 из PowerShell после `robocopy` не ошибка (смотреть на хэши и на то, что скрипт дошёл до конца).

Результат последнего живого прогона: простой UI 0.40 % CPU / 121 МБ, движок 0.27 % / 102 МБ, `--quit` завершает оба процесса и удаляет сокет.

## Скриншоты и IPC, 1 ноября поздно вечером (проверено вживую: 3 прогона Win+Shift+S подряд)

- Оверлей Snipping Tool (`XamlWindow`) Windows ужимает до рабочей области, раз панель и док резервируют место: он показывал уменьшенный замороженный экран, а живые панель с доком оставались яркими снаружи. Теперь `CaptureOverlayMonitor.FitOverlayToMonitor` растягивает его на весь монитор, а `PlaceUiWindows` (движок, без участия Dart) опускает окна `FloatingDock.UiWindow` с WS_EX_TOPMOST под оверлей и возвращает после. Яркость панели и дока во время оверлея падает так же, как у обоев.
- Окно дока после `HWND_NOTOPMOST` не брало обычный `HWND_TOPMOST` (вызов успешен, ничего не меняется): нужна пара NOTOPMOST → TOPMOST (`MakeTopmost`). Таймер `HealUiWindows` (700 мс) поднимает окно, потерявшее флаг вне съёмки, и пишет это в `engine.log`.
- Детектор оверлея: покрытие считается по рабочей области, а не по всему монитору; сразу после шортката допускается окно без WS_EX_TOPMOST. `engine.log` пишет описание окон Snipping Tool, `capture overlay detected`, `z-order: ...`.
- C++ `WindowHost::Show` поднимает окно только если `raise` (Dart передаёт `!WindowHost.underOverlay`) и окно создавалось topmost (`HostWindow.topmost`).
- Сборка в одну папку: `.validation\dist5` (перед пересборкой `FloatingDock.Engine.exe --quit`, затем `make-dist.ps1 -SkipClassic -Engine ..\.validation\engine5 -Out ..\.validation\dist5`).
- Тряска при скриншоте: Snipping Tool сам ужимает окно оверлея до рабочей области (два раза за первые 400 мс, на каждое наше перемещение отвечает тем же). Таймер на 100 мс давал видимые рывки и полосы. Теперь `WatchOverlaySize` ставит WinEvent-хук `EVENT_OBJECT_LOCATIONCHANGE` на окно оверлея и возвращает его на весь монитор сразу после каждого сдвига (не более 400 раз за съёмку). Замер с шагом 1 мс: окно всё время 0,0,1920,1080.
- Остаток дрожи: приложение ужимает оверлей дважды (через ~60 мс после показа и ещё раз через ~60 мс после нашего возврата). Теперь оверлей опознаётся по `EVENT_OBJECT_SHOW` (`WatchOverlayShown`, ~6 мс после показа вместо опроса раз в 30 мс), а возврат размера идёт хуком `EVENT_OBJECT_LOCATIONCHANGE`. После съёмки окна возвращаются «поверх всех» повторами каждые 30 мс (`RetryRaise`): окно дока с первого раза флаг не берёт, обычно хватает одной повторной попытки (~40 мс). Полностью убрать два сжатия нельзя без снятия резерва рабочей области (сдвинет развёрнутые окна), поэтому остаётся не более одного кадра на каждое.

- **Пресеты иконок в стиле macOS делались и были откачены по просьбе пользователя** (плашка-суперэллипс, перекраска по яркости, Dark/Vivid/Light и 9 цветов). Кода не осталось (ни настроек `IconStyle`/`IconTint`, ни тестов). Если вернуться к идее: картинки UWP-тайлов лучше обрезать по плашке, а не класть на неё.
- **Превью окон**:
  - Плашка с именем приложения (`ShowLabels`) оставалась позади открытого превью и выглядывала из-под него. `DockModel.previewActive` (ставит `DockController._setLabelsAside` при показе и закрытии превью) гасит плашку, пока превью открыто.
  - Свёрнутое окно DWM не рисует, и карточка показывала только иконку. Движок теперь хранит последние снимки окон (`FloatingDock.Windows/WindowManagement/WindowSnapshotCache.cs`, до 24 окон, до 480x320, только в памяти): `PrintWindow` с `PW_RENDERFULLCONTENT` в момент `MinimizeStart` и когда окно теряет фокус (не чаще раза в 2 с, `EngineHost.Snapshots.cs`); свёрнутые и зависшие окна не снимаются, снимок забывается при `Destroyed`. Метод IPC `window.snapshot {hwnd} -> {image: base64 PNG | null}`. `PreviewLayout.snapshot` рисуется в карточке свёрнутого окна (приглушён, `BoxFit.cover`), без снимка остаётся иконка. Захват через `PrintWindow` на Zen проверен; окно, свёрнутое до запуска дока, снимка не имеет.
- **Закрепы с панели задач** при первом запуске уже работали: `EngineHost.Start` (`firstRun = !File.Exists(PinnedFile)`) один раз вызывает `SeedPinnedFromWindowsTaskbarAsync`; потом проверок нет. Ручной импорт: Настройки → Dock.
- **Замер нагрузки (7 ноября, релиз 2.0.1, диагностический профиль)**: простой UI 0,2 % одного ядра, движок около 0 %, GPU 0 %, кадров Flutter 0 за 5 с; наведение на док около 2 % ядра (растеризация ~2,7 мс на кадр); память UI ~115 МБ + движок ~108 МБ. Более высокие числа давали сами замеры (счётчики потоков, `dart run` рядом). Движок в диагностическом режиме пропускает таймеры языка и области (`_diagnostic`), поэтому его настоящую нагрузку не мерили. Таймеры дока/бара (100 мс у края, часы 1 с, медиа 2 с, батарея 30 с) можно слить, но выигрыш ничтожный; скрытые окна и док в покое уже не рисуют. Рычаги, если понадобятся: лимит кадров 30, меньше памяти через Native AOT / один процесс.
- **Осторожно с живыми тестами**: пользователь работает за этим же ПК. Обычный (недиагностический) запуск прячет панель задач и показывает док; `--quit` без `--diagnostic-profile` не гасит диагностический экземпляр (`FloatingDock.exe --diagnostic-profile <папка> --quit`). Полноэкранные снимки захватывают его вкладки: снимать только область дока.

## Док и панель «точь в точь» по скриншотам, 8 ноября (вечер)

Пользователь прислал три картинки (док и панель из видео, и свой док) и велел повторить док и панель точь-в-точь; у панели должно быть три вида: как на картинке, таблетки, до краёв экрана (плюс прежний `Text`). Не закоммичено.

- **Док** (`dock_view.dart`): при `BottomOffset = 0` плита прижата к краю экрана: скруглена только со свободной стороны (`CornerRadius`), под обоими концами вогнутые «крылья» радиуса `flushWing` = 12 (`_flushPlate`, строится в координатах (вдоль, поперёк) и переводится `DockAxis.point`, поэтому работает для Bottom/Left/Right); без тени и рамки. При `BottomOffset > 0` прежняя плавающая плита. Плитка под иконкой теперь выходит за иконку на `(IconSpacing - 4) / 2` (мин. 2), так что зазор между плитками 4 px.
